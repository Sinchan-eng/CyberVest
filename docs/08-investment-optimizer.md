# Investment Optimization Engine

## 1. Purpose

The Investment Optimization Engine determines how a fixed cybersecurity budget should be allocated across available remediation and security-control options.

The objective is to select a set of investments that maximizes **expected financial cyber-risk reduction** while ensuring that the total investment cost does not exceed the user's available budget.

The engine must be:

- Transparent
- Deterministic
- Explainable
- Reproducible
- Easy to test
- Independent of an LLM for numerical calculations

AI may explain results in natural language, but must not invent costs, risk reductions, or optimization results.

---

## 2. Objective

Given:

- Current cyber-risk exposure
- A set of possible security investments
- Expected risk reduction for each investment
- Cost of each investment
- A fixed cybersecurity budget

Select investments such that:

```text
Total Investment Cost <= Budget
```

while maximizing:

```text
Total Expected Risk Reduction
```

The engine should answer questions such as:

- "How should I spend ₹5 lakh to reduce the most financial cyber risk?"
- "Which controls should we implement first?"
- "What risk reduction can we achieve with ₹10 lakh?"

---

## 3. Scope

The MVP optimizer operates on pre-calculated investment options.

The optimizer does **not** independently determine:

- Vulnerability severity
- Asset criticality
- Financial impact
- Probability of exploitation
- Risk exposure
- Control effectiveness

Those values must come from the existing risk quantification engine or validated input data.

The optimizer only determines the best allocation of the provided budget.

## 6. Budget

The user provides a fixed cybersecurity budget.

Example:

```json
{
  "budget": 500000
}
```

The fundamental constraint is:

```text
sum(selected investment costs) <= budget
```

The optimizer must never return a selection whose total cost exceeds the provided budget.

A budget of zero must return no investments.

---

## 7. Optimization Metric

For each investment calculate:

```text
Risk Reduction per Rupee =
Expected Risk Reduction / Investment Cost
```

This represents the amount of expected financial risk reduction generated by every rupee invested.

Example:

```text
Investment:
Cost = ₹2,00,000
Expected Risk Reduction = ₹10,00,000

Risk Reduction per Rupee
= 10,00,000 / 2,00,000
= 5
```

Therefore, every ₹1 invested is expected to reduce ₹5 of financial risk.

---

## 8. MVP Optimization Algorithm

The MVP uses a **greedy optimization algorithm** because it is simple, deterministic, transparent, and easy to explain.

A full 0/1 knapsack implementation may be introduced later if exact optimization is required.

### 8.1 Greedy Algorithm

#### Step 1 — Validate inputs

Validate:

- Budget is numeric
- Budget is greater than or equal to zero
- Every investment has a unique ID
- Cost is greater than zero
- Expected risk reduction is greater than or equal to zero
- Required fields are present
- Investment IDs are not duplicated

Invalid investments must not silently enter the optimization calculation.

They should either be rejected during validation or returned as validation errors.

#### Step 2 — Calculate efficiency

For each valid investment:

```text
efficiency =
expected_risk_reduction / cost
```

#### Step 3 — Sort investments

Sort investments by:

1. Highest risk reduction per rupee
2. Higher priority
3. Higher expected risk reduction
4. Stable ID ordering

The final ID ordering provides deterministic behavior when all other values are equal.

#### Step 4 — Select investments

Starting with the highest-ranked investment:

```text
if investment.cost <= remaining_budget:
    select investment
    remaining_budget -= investment.cost
else:
    skip investment
```

Continue until all investments have been evaluated.

#### Step 5 — Calculate final metrics

Calculate:

- Total investment
- Total expected risk reduction
- Remaining budget
- Before exposure
- After exposure
- Percentage reduction
- ROSI

---

## 9. Greedy Pseudocode

```text
function optimize(investments, budget, before_exposure):

    validate budget

    valid_investments = validate_and_deduplicate(investments)

    for investment in valid_investments:
        investment.efficiency =
            investment.expected_risk_reduction / investment.cost

    sort valid_investments by:
        efficiency DESC
        priority DESC
        expected_risk_reduction DESC
        id ASC

    selected = []
    remaining_budget = budget

    for investment in valid_investments:

        if investment.cost <= remaining_budget:

            selected.append(investment)

            remaining_budget =
                remaining_budget - investment.cost

    total_investment =
        sum(investment.cost for investment in selected)

    total_risk_reduction =
        sum(investment.expected_risk_reduction
            for investment in selected)

    after_exposure =
        max(0, before_exposure - total_risk_reduction)

    if before_exposure > 0:
        percentage_reduction =
            (total_risk_reduction / before_exposure) * 100
    else:
        percentage_reduction = 0

    if total_investment > 0:
        rosi =
            ((total_risk_reduction - total_investment)
            / total_investment) * 100
    else:
        rosi = null

    return result
```

---

## 10. Important MVP Assumption

The greedy approach optimizes based on **risk reduction per rupee**.

It does not guarantee the mathematically optimal combination for every possible budget.

For example, a combination of two lower-efficiency controls could theoretically produce greater total risk reduction than one high-efficiency control.

The MVP intentionally accepts this trade-off in exchange for:

- Simplicity
- Speed
- Explainability
- Easy implementation
- Easy debugging
- Deterministic results

A future version may support exact 0/1 knapsack optimization.

---

## 11. Investment Dependencies

The MVP assumes that investment options are independent.

For example:

```text
MFA
EDR
Critical Patching
Network Segmentation
```

are treated as independent options.

The optimizer does not currently model:

- Dependencies
- Mutually exclusive controls
- Synergistic controls
- Diminishing returns
- Overlapping risk reduction
- Multi-year costs
- Operational constraints

These can be added in future versions.

---

## 12. Avoiding Double Counting

Expected risk reduction values must be generated by the risk engine in a way that avoids double counting the same risk.

For example, if both MFA and EDR reduce the same risk:

```text
MFA reduction = ₹5 lakh
EDR reduction = ₹6 lakh
```

The optimizer must not automatically assume:

```text
Total reduction = ₹11 lakh
```

unless the underlying risk model explicitly states that these reductions are additive.

For the MVP, `expected_risk_reduction` values supplied to the optimizer are assumed to already account for the relevant risk model.

The optimizer must not invent additional reduction values.

## 15. Before and After Exposure

The optimizer should show the financial risk before and after investment.

Formula:

```text
After Exposure =
max(0, Before Exposure - Expected Risk Reduction)
```

Example:

```text
Before Exposure = ₹30 lakh
Expected Risk Reduction = ₹19 lakh

After Exposure = ₹30 lakh - ₹19 lakh
               = ₹11 lakh
```

The `max(0, ...)` prevents the system from producing negative financial exposure.

---

## 16. Percentage Risk Reduction

Formula:

```text
Percentage Reduction =
(Expected Risk Reduction / Before Exposure) × 100
```

Example:

```text
Before Exposure = ₹30 lakh
Expected Risk Reduction = ₹19 lakh

Percentage Reduction =
(19 / 30) × 100
= 63.33%
```

### Zero Exposure

If:

```text
before_exposure = 0
```

the percentage reduction must be:

```text
0%
```

rather than causing a division-by-zero error.

---

## 17. ROSI

The MVP defines Return on Security Investment as:

```text
ROSI =
(Risk Reduction - Investment Cost)
/
Investment Cost
× 100
```

All values must use INR.

Example:

```text
Risk Reduction = ₹19 lakh
Investment Cost = ₹3 lakh

ROSI =
(19 - 3) / 3 × 100

= 533.33%
```

This means the expected financial risk reduction exceeds the investment cost by approximately 533.33%.

### Zero Investment

If:

```text
Investment Cost = 0
```

ROSI is undefined.

The API should return:

```json
{
  "rosi": null
}
```

rather than producing infinity or an error.

## 29. Future 0/1 Knapsack Optimization

A future version can implement 0/1 knapsack.

The optimization objective would be:

```text
maximize:
Σ expected_risk_reduction_i × x_i
```

subject to:

```text
Σ cost_i × x_i <= budget
```

where:

```text
x_i ∈ {0, 1}
```

`x_i = 1` means the investment is selected.

`x_i = 0` means the investment is not selected.

The knapsack approach can find the mathematically optimal combination, unlike the greedy MVP.

The API should be designed so that the optimization algorithm can later be replaced without changing the frontend contract.

## 33. AI Safety Constraint

The optimizer is a financial/cybersecurity decision-support component.

The AI layer must not:

- Invent investment costs
- Invent expected risk reductions
- Change optimizer results
- Claim an investment is selected when it was not
- Claim an investment was rejected for a reason not produced by the optimizer
- Modify ROSI
- Modify exposure calculations
- Create unsupported financial assumptions

Correct architecture:

```text
Validated Data
      ↓
Risk Engine
      ↓
Investment Options
      ↓
Deterministic Optimizer
      ↓
Calculated Results
      ↓
AI Explanation
```

The AI explains the deterministic result; it does not generate the underlying financial calculation.

The CyberQuant AI Investment Optimization Engine uses a transparent greedy algorithm for the MVP.

The core decision rule is:

```text
Risk Reduction per Rupee =
Expected Risk Reduction / Investment Cost
```

The optimizer:

1. Validates investment options.
2. Calculates risk reduction efficiency.
3. Sorts investments by efficiency.
4. Selects investments that fit within the remaining budget.
5. Calculates total investment.
6. Calculates expected risk reduction.
7. Calculates remaining budget.
8. Calculates before/after exposure.
9. Calculates percentage risk reduction.
10. Calculates ROSI.
11. Provides an explanation for every selection and rejection.

This provides a simple, auditable foundation for CyberQuant AI's investment decision-support capability while leaving room for future optimization algorithms such as 0/1 knapsack, dependency-aware optimization, and multi-period security investment planning.
